# Context strategy evaluation contract

Run `go run ./examples/context_evaluation` for JSON offline results. The runner compares sliding window, rolling summary, explicit offload and host-selected retrieval with the same corpus, input capacity, estimator and evaluator. All ports, fixture identities and policies are local host types. No provider SDK, credentials or network client belongs to contexty.

Every row records the actual selected semantic messages and exact content references, pinned policy identities and actual policy thresholds, complete issued-content estimate reports of issued content, original input exclusions, strategy callback counts and host wall-clock duration. Independent adversarial behavior preflights are recorded once per fixture in `behaviors`, outside each strategy row. Timing is diagnostic and excluded from reproducibility comparisons. Offline model quality, provider usage and money are `not measured`; character estimates are never priced as provider tokens. Fixture fact checks prove only deterministic preservation, source attribution, constraints and protocol mechanics. They do not establish LLM answer quality or resistance to retrieved instructions.

Rolling summary processes chronological atomic steps (a completed tool round and the following ordinary host message form one step, so a giant completed result is not an impossible protected recent tail) and feeds the previous working result into later compaction. Its deterministic fixture callback keeps explicit `FACT` markers and their sources. This is an intentionally privileged fixture summarizer, not an LLM. Sliding window exposes fact loss. Offload explicitly stores completed tool evidence as typed artifacts before compiling previews; pending calls are never rewritten. Retrieval searches host source IDs and passes only selected descriptors through bounded, authorized ResourceResolver reads. Summaries and working windows are not archives.

`evaluation.RunLive` is an opt-in host runner with typed Model, Summarizer and Evaluator ports. A host must invoke it explicitly and supply pinned identities, estimator, number of runs and adapters. The offline command cannot enable a provider by flag or environment variable. A host executable calls this port after its own SDK/credential initialization; ordinary tests use mechanical test adapters only. Live reports contain only usage/cost values actually returned by the adapter and evaluation values actually returned by its evaluator. Usage and cost cover only final answer generation; summarizer and evaluator provider usage/cost are `not measured` because their typed ports do not return those observations. Missing measurements remain `not measured`. Provider results are not a universal ranking of strategies.

The in-memory blob/resource adapters in this example are process-local fixtures. See [blob retention](../../docs/blob-retention.md) and [resource content](../../docs/resource-content.md) for durable retention claims, scopes, authorization and bounded restore. Offload reduces issued context, while exact replay capture may retain original private bytes. Capture is a separate retention decision. The external-context cookbook shows checkpoint/claims composition; this evaluation does not claim durability across process restarts.
